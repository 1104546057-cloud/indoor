# 项目开发记录（2026-08-02）

## 1. 版本概述

本次版本围绕“任务可管理、首页可演示、实时资源可控”完成两组功能升级：

1. 巡检任务列表支持打开大尺寸任务详情窗口，查看路线、巡检点、任务状态和可执行操作。
2. 未执行任务支持编辑，能够修改任务参数、巡检点顺序、到点朝向和计划开始时间。
3. 学校级首页固定展示 22 台巡检车，并根据车辆状态在实时视频、3D 路线回放和静态预览之间自动切换。
4. 对浏览器中的视频与 WebGL 资源进行统一限额，实时巡检车辆优先使用渲染资源。

本版本没有新增数据库表或字段，不需要执行数据库迁移。

## 2. 巡检任务详情窗口

### 2.1 打开方式

在“巡检任务管理”页面点击任务列表中的任意任务行，会打开任务详情大窗口。弹窗集中展示：

- 任务名称、任务编号、状态和执行进度；
- 执行机器人、巡检区域、优先级和计划开始时间；
- 有序巡检点、点位坐标和到点朝向；
- 实验楼一任务地图、路线连线和点位序号；
- 与当前状态匹配的开始、编辑、监控、暂停、继续和删除按钮。

### 2.2 路线地图交互

待执行任务的路线图支持：

- 鼠标按住拖动地图；
- 鼠标滚轮缩放；
- “＋”“－”按钮缩放；
- 双击恢复默认视图；
- 按任务保存顺序绘制路线和序号；
- 显示到点朝向箭头。

已开始任务的地图作为执行视图使用，避免操作人员把地图浏览误认为路线编辑。

### 2.3 任务操作约束

操作按钮会根据任务状态显示：

| 任务状态 | 可用操作 |
| --- | --- |
| 待执行 | 编辑、开始、删除 |
| 执行中 | 实时监控、暂停 |
| 已暂停 | 实时监控、继续、删除 |
| 已完成/异常 | 查看详情、报告或记录入口 |

执行中的任务不能直接删除；已经启动、存在执行记录或进度大于 0 的任务不能修改任务参数和路线。

## 3. 未执行任务编辑

### 3.1 前端流程

点击待执行任务的“编辑”后，复用新建巡检计划两步式窗口：

1. 自动回填任务名称、执行机器人、开始日期、开始时间和优先级。
2. 自动恢复已经保存的有序巡检点、自由点坐标与到点朝向。
3. 允许重新排序、删除或补充巡检点。
4. 点击“保存修改”后保持原任务 ID 不变，并刷新任务列表和详情窗口。

编辑过程中会再次检查当前任务状态。如果任务已经被其他操作启动，前端停止保存并提示状态已变化。

### 3.2 后端接口

新增接口：

```http
PUT /api/tasks/{task_id}
Content-Type: application/json
```

接口使用与新建任务一致的 `InspectionTaskCreate` 数据结构，主要安全约束如下：

- URL 中的任务 ID 必须与请求体 ID 一致；
- 任务必须处于 `pending` 或“待执行”状态；
- 任务进度必须为 0；
- 数据库中不能存在对应执行记录；
- 更新时重建并持久化有序路线点；
- 已执行任务返回 HTTP 409，任务不存在返回 HTTP 404。

后端抽取 `_build_task_route_points()`，让创建与编辑共用路线点持久化逻辑，避免点位名称、坐标、顺序和朝向字段在两个接口中产生差异。

## 4. 学校级 22 台车监控墙

### 4.1 首页展示逻辑

学校级首页固定生成 22 个车辆窗口，不再只展示当前在线车辆。窗口按照以下优先级排序：

1. 正在巡检；
2. 存在识别异常；
3. 任务执行中但车辆断联；
4. 在线空闲；
5. 离线。

车辆数据会关联真实车辆注册表、机器人业务档案、当前执行记录和最近一次历史记录。执行中的记录与历史回放记录分开保存，避免已完成任务被错误判断为正在巡检。

### 4.2 画面选择策略

每个车辆窗口按状态选择内容：

- 在线且任务执行中：显示一路主摄像头实时画面；
- 没有执行中任务但存在历史任务：回放最近任务的保存路线；
- 没有任何历史数据：回放实验楼一内置演示路线；
- 不在动态资源名额内：显示路线回放静态预览图。

这样即使演示现场没有真实车辆在线，首页仍然能够展示完整的 22 车监控效果，同时通过 `DEMO`、`REPLAY`、`STATIC` 和 `LIVE` 标识区分演示、历史与实时数据。

## 5. 3D 路线模拟回放

### 5.1 回放内容

3D 回放使用 Three.js 根据地图数据生成：

- 地面网格、墙体、走廊和房间；
- 电柜、立柱等场景对象；
- 有序路线、巡检点标记和移动中的车辆模型；
- 随车辆位置变化的跟随相机。

缩略窗口使用低帧率动画，单车详情使用更高帧率的完整 3D 跟随视角。回放仅用于页面演示和历史过程表达，不会向真实车辆下发导航命令，也不会生成实时识别结果。

### 5.2 动态资源限额

首页设置统一动态资源上限：

```text
实时视频路数 + 3D 动画路数 <= 6
```

资源分配规则：

1. 当前可见且正在巡检的实时车辆优先占用视频名额。
2. 剩余名额分配给当前可见的 3D 路线回放。
3. 其余车辆退化为无 WebGL 开销的 SVG 静态预览。
4. 元素离开可视区域后，`IntersectionObserver` 自动停用对应视频或 3D 动画。
5. 浏览器标签页进入后台后暂停动画帧更新。

例如存在 1 台实时巡检车时，首页分配为 1 路实时视频、5 路 3D 回放和 16 路静态预览。

### 5.3 单车详情

点击任意车辆进入二级详情：

- 执行中车辆显示高位、中位、低位和云台四路摄像头；
- 非执行中车辆启用一幅完整 3D 跟随回放；
- 下方同步展示二维地图、完整有序路线、巡检点和任务摘要；
- 没有历史任务时显示“实验楼一演示路线”、12 个演示巡检点和“路线模拟回放”状态。

只有选中的真实执行车辆会轮询 `/api/vehicle/status`，历史或演示回放不会产生无意义的车辆状态请求。

## 8. 使用与维护说明

- 演示回放不等于真实车辆在线，页面必须保留 `DEMO/REPLAY/LIVE` 状态标识。
- 首页动态资源上限由 `MAX_ACTIVE_VISUALS` 控制，默认值为 6；不建议在普通办公电脑上盲目提高。
- 真实车辆主摄像头角色使用 `movement`，详情四路摄像头角色使用 `high`、`middle`、`low` 和 `ptz`。
- 路线回放优先使用任务保存的 `routePoints`；没有历史路线时才使用实验楼一 `inspectionPoints`。
- 任务编辑接口只面向未执行任务，不应放宽对执行记录的校验，否则会破坏巡检档案可追溯性。
