# 实验楼一巡检实时监控使用指南

## 1. 功能范围

`/patrol-3d` 现在支持监控实验楼一正在执行的有序巡检路线：

- 读取 Nano 的 `map → base_link`，显示小车真实位置与朝向。
- 读取车端 `move_base` 路线状态，显示当前点、已到达点数和执行结果。
- 显示车载 MJPEG 实时视频。
- 使用 `execution_id` 识别本次路线，刷新网页后可从当前浏览器会话恢复。
- 车辆或后端断线后显示离线并保留最后状态，不继续播放虚假路线。
- 只有带 `replay=1` 的回放入口才使用本地演示动画。

该功能不会自动启动底盘、导航栈或车辆巡检。

## 2. 需要部署到 Nano 的文件

```text

```

```text

```

在项目根目录的 PowerShell 中复制：

```powershell
scp .\vehicle\vehicle_agent.py nano1@192.168.31.139:/home/nano1/indoor_patrol_ws/src/indoor_patrol_bringup/scripts/vehicle_agent.py
```

然后在 Nano 终端赋予执行权限：

```bash
chmod +x /home/nano1/indoor_patrol_ws/src/indoor_patrol_bringup/scripts/vehicle_agent.py
```

如果旧 `vehicle_agent` 正在运行，需要在安全停车后重启该节点，才能加载新代码。不要因此重复启动第二套底盘、雷达、AMCL 或 `move_base`。

运动摄像头使用用户级 systemd 服务自动恢复：

```text
本地：vehicle/indoor-patrol-movement-camera.service
Nano：~/.config/systemd/user/indoor-patrol-movement-camera.service
```

检查与重启命令：

```bash
systemctl --user status indoor-patrol-movement-camera.service
systemctl --user restart indoor-patrol-movement-camera.service
curl http://127.0.0.1:8080/status
```

## 3. 车端检查

确认导航栈已经正常运行：

```bash
rosnode list | egrep 'amcl|map_server|move_base|vehicle_agent'
rosrun tf tf_echo map base_link
rostopic echo -n 1 /amcl_pose
```

检查车端 HTTP 数据：

```bash
curl http://127.0.0.1:9000/status
curl http://127.0.0.1:9000/navigation_route/status
```

`/status` 应包含：

```json
{
  "online": true,
  "pose": {
    "frame_id": "map",
    "child_frame_id": "base_link",
    "x": 0.0,
    "y": 0.0,
    "yaw": 0.0
  },
  "localization": {
    "valid": true,
    "pose_age": 0.1
  },
  "navigation": {
    "state": "idle"
  }
}
```

如果 `localization.valid` 为 `false`，监控页不会把该位姿当作可信实时位置。应先处理 TF、AMCL 协方差或位姿超时问题。

## 5. 使用流程

1. 在 RViz 中完成 AMCL 初始定位，确认激光与 `first_floor` 地图重合。
2. 在前端创建实验楼一巡检任务，并按顺序选择固定点或自定义点。
3. 点击任务行的“开始”。车端接收后会返回唯一 `execution_id`。
4. 任务状态变为“执行中”后，点击该行的“监控”。
5. 页面显示：
   - `REAL-TIME / 车辆在线`；
   - 真实车辆速度和电压；
   - 定位状态“可信”；
   - `已到达点数 / 总点数`；
   - 车端当前路线状态；
   - 车载实时视频。
6. 刷新页面时，浏览器通过查询参数和 `sessionStorage` 恢复当前执行。

监控地址示例：

```text
http://localhost:5173/patrol-3d?execution_id=route-xxxx&vehicle_id=nano1&task_id=task-xxxx
```

直接访问 `/patrol-3d` 时会尝试恢复本浏览器最近一次执行；没有执行记录时显示等待路线，不会自动模拟车辆运动。

## 6. 后端接口

查询车辆状态：

```http
GET /api/vehicle/status?vehicle_id=nano1
```

查询本次路线：

```http
GET /api/vehicle/navigation-route/status?vehicle_id=nano1&execution_id=route-xxxx
```

停止当前路线：

```http
POST /api/vehicle/navigation-route/cancel
Content-Type: application/json

{
  "vehicle_id": "nano1",
  "execution_id": "route-xxxx"
}
```

页面上的“停止巡检”会先要求确认，然后调用取消接口。当前实现不提供从中间点无缝恢复；停止后如需继续，应重新核对路线和现场安全后重新下发。

## 7. 验收方法

不需要实际启动车辆也可以先完成静态验收：

```powershell
Set-Location .\frontend
npm run build
```

联机验收时再检查：

1. 页面位置与 `rosrun tf tf_echo map base_link` 一致。
2. 车端 `reached_count` 增加后，网页进度才增加。
3. 断开 Nano 网络后，网页变为离线且图标不继续移动。
4. 恢复网络后，网页继续读取同一个 `execution_id`。
5. 路线完成后状态为 `completed`，到达数量等于总点数。
