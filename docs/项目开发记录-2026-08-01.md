3. 修复设备管理中的关联数据错误、跨标签选中残留、车辆电量缺失、状态重复以及轮询失败耦合；

8. 增加数据库迁移和部署说明。

## 2. 学校级 22 台车监控首页

### 2.1 一级车辆总览

首页入口切换为 `SchoolFleetDashboard`，固定生成 22 个车辆槽位。已注册车辆会合并真实连接状态、数据库机器人档案和正在执行的巡检记录；未注册槽位保留编号和离线占位状态。

一级页面具有以下能力：

- 每台车只展示一路 `movement` 行驶主摄像头；
- 根据当前展示车辆数量计算网格列数，自动调整监控墙布局；
- 支持按车辆或电房查看；
- 车辆按告警、巡检中、在线空闲、离线的优先级排序；
- 显示固定车辆总数、在线车辆数、执行中任务数和告警数；
- 视频不可用时显示明确的未配置、等待上线或连接失败占位状态，并提供重新连接操作。

### 2.2 二级单车任务详情

点击某台车后进入单车详情，页面包含：

- 高位摄像头：`camera_streams.high`；
- 中位摄像头：`camera_streams.middle`；
- 低位摄像头：`camera_streams.low`；
- 云台摄像头：`camera_streams.ptz`；
- 实时地图、车辆位置、车辆朝向和有序路线；
- 路线已到达点、当前点和待到达点状态；
- 任务进度、任务编号、当前点位、异常和识别结果摘要。

地图会根据任务场景选择对应的地图配置，并将 SLAM 米制坐标转换到前端模型坐标。车辆姿态优先读取实时遥测四元数或 yaw，路线进度优先读取车辆导航状态。

### 2.3 车辆摄像头配置格式

车辆注册表新增 `camera_streams`：

```json
{
  "camera_streams": {
    "movement": "http://车辆IP:8080/",
    "high": "http://车辆IP:8081/",
    "middle": "http://车辆IP:8082/",
    "low": "http://车辆IP:8083/",
    "ptz": "http://车辆IP:8084/"
  }
}
```

旧配置中的 `camera_stream_url` 和 `movement_camera_stream_url` 仍然兼容，新页面优先使用带角色的 `camera_streams`。

## 3. 设备管理数据正确性修复

### 3.1 关联资源

- 电柜根据 `roomId` 关联所属电房；
- 监测对象根据 `cabinetId` 关联电柜；
- 监测对象可通过 `inspectionPointId` 直接绑定巡检点；
- 电柜详情聚合其下监测对象及巡检点；
- 车辆详情根据车辆业务编码匹配巡检记录，再从任务路线中汇总关联巡检点；
- 当前设备的巡检记录和告警不再展示其他设备的数据。

### 3.2 页面选中状态

切换“设备总览、巡检机器人、电房档案、电柜档案、监测对象、阈值规则”时，会清空旧标签的选中 ID、搜索词、状态筛选和分页，避免不同资源主键相同导致错误详情被选中。

### 3.3 车辆状态与轮询

- 业务概览请求和车辆状态请求改为独立完成，单个接口失败不会清空另一个接口的有效数据；
- 多车状态探测并发执行，并增加短时心跳缓存；
- 单台车辆探测抛出异常时只更新该车错误状态，不会导致整个车辆列表返回失败；
- 车辆返回电量、电压、最后响应时间、检查时间和错误原因；
- 页面只展示一次规范化状态，取消重复的在线/离线业务字段。

## 4. 设备资源 CRUD

### 4.1 支持的资源

| 资源 | 新增 | 查看 | 编辑 | 停用 | 受控删除 |
| --- | --- | --- | --- | --- | --- |
| 电房 | 支持 | 支持 | 支持 | 支持 | 检查电柜、巡检点和路线引用 |
| 电柜 | 支持 | 支持 | 支持 | 支持 | 检查监测对象、巡检点和现场图片引用 |
| 监测对象 | 支持 | 支持 | 支持 | 支持 | 检查识别结果和告警引用 |
| 阈值规则 | 支持 | 支持 | 支持 | 支持 | 无历史依赖时允许删除 |
| 巡检机器人 | 支持 | 支持 | 支持 | 支持 | 检查任务和巡检记录引用 |

普通删除操作默认执行软停用，保留历史数据和业务关系。只有显式传入 `hard=true` 才会尝试物理删除；存在依赖时后端返回 HTTP 409，并说明阻止删除的引用数量。新增、编辑、停用和删除操作均写入系统操作日志，管理写操作要求管理员权限。

### 4.2 主要接口

```text
POST   /api/business/rooms
PUT    /api/business/rooms/{id}
DELETE /api/business/rooms/{id}?hard=false

POST   /api/business/cabinets
PUT    /api/business/cabinets/{id}
DELETE /api/business/cabinets/{id}?hard=false

POST   /api/business/device-items
PUT    /api/business/device-items/{id}
DELETE /api/business/device-items/{id}?hard=false

POST   /api/business/threshold-rules
PUT    /api/business/threshold-rules/{id}
DELETE /api/business/threshold-rules/{id}?hard=false

POST   /api/business/robots
PUT    /api/business/robots/{id}
DELETE /api/business/robots/{id}?hard=false
```

阈值提交时会检查上下限顺序，防止保存最小值大于最大值的无效规则。巡检识别时只选择启用的阈值规则，并按规则 ID 确定性排序，避免多条规则导致结果随机变化。

## 5. 车辆档案与心跳管理

### 5.1 双数据源职责

- `backend/vehicles.json`：保存 Agent、SSH、启动脚本和摄像头地址等本机连接参数；
- `tb_robot`：保存机器人业务档案、启用状态、最近心跳、电量、电压和故障原因。

设备管理页面保存车辆时会同时更新连接注册表和数据库档案。读取 `/api/vehicles` 时，系统会将注册表车辆幂等同步到 `tb_robot`，并将数据库主键、启用状态和心跳结果合并后返回前端。

### 5.2 安全处理

- SSH 密码只写入本机 `vehicles.json`，不会从车辆列表接口回传前端；
- `vehicles.json` 保持为本地配置，不提交真实密码；
- 前端编辑车辆时密码留空表示沿用原密码；
- 车辆编号创建后不可修改，避免历史任务和巡检记录失去关联。

## 6. 视觉业务配置

### 6.1 监测对象新增字段

- `recognition_type`：识别算法/业务类型，例如 `meter`、`lamp`、`switch`；
- `camera_role`：采集该目标的摄像头角色；
- `reference_image_url`：识别参考图片；
- `inspection_point_id`：绑定的巡检点；
- `roi_x`、`roi_y`、`roi_width`、`roi_height`：百分比坐标形式的 ROI。

### 6.2 图片上传与 ROI

管理端允许上传 PNG、JPEG 和 WebP 图片，单张最大 5 MB。文件保存到 `backend/uploads`，目录已加入 `.gitignore`，数据库只保存访问地址。

```text
POST /api/business/assets/image
GET  /api/business/assets/{asset_name}
```

上传参考图后，可在图片上按住鼠标拖动形成 ROI。前端将坐标转换为相对图片区域的百分比，因此不同分辨率下仍可复用同一框选范围。

## 11. 部署与验收顺序

1. 备份目标数据库并停止旧后端；
2. 拉取本次提交；
3. 检查 `backend/.env` 的数据库连接；

## 12. 注意事项

- 物理删除属于高风险操作，前端会再次确认，后端仍会执行引用检查；日常维护优先使用“停用”；
- 四路任务摄像头只有配置对应 `camera_streams` 地址后才能显示真实画面；
- 车辆离线不会影响业务主数据读取，页面会保留最近一次心跳时间和故障原因；
- 图片上传目录不进入 Git，生产部署时应单独规划持久化磁盘和备份策略；
- 本次只完善设备管理和监控业务配置，不会自动启动小车或下发巡检任务。
