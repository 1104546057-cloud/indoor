# 实验楼一固定与自定义巡检点有序路线使用指南

## 1. 已实现的能力

本功能使用实验楼一的 `first_floor.yaml` 地图。用户可在“巡检任务管理”页面选择多个固定巡检点，或直接在 SLAM 地图白色自由空间中创建自定义巡检点，调整点位先后顺序和到点朝向，然后一次性将整条路线下发给 `nano1`。

车端不会同时发送所有导航目标，而是严格执行以下流程：

1. 接收并保存完整有序路线，生成唯一的 `execution_id`。
2. 将第一个点发送给 ROS `move_base`。
3. 只有收到 `GoalStatus.SUCCEEDED` 后，才记录该点到达成功并发送下一个点。
4. 全部点依次成功后，将路线状态设为 `completed`。
5. 任一点失败、被拒绝或导航中止时，立即停止整条路线并返回失败点和错误原因。

前端每秒查询一次车端执行状态，以车端返回的 `reached_count` 更新任务进度。只有车端确认所有点均已到达，前端才把任务标记为完成。

## 3. 启动前检查

1. 将小车放在实验楼一地图对应的真实区域内，保证急停按钮、底盘、雷达和网络工作正常。
2. 确认操作电脑和 Nano 能互相访问，Nano 地址为 `192.168.31.139`。
3. 打开小车终端，但先不要点击任务“开始”。
4. 启动车端服务：

```bash
bash /home/nano1/indoor_patrol_ws/src/indoor_patrol_bringup/scripts/start_vehicle_services.sh
```

5. 等待约 10 秒后检查车端代理：

```bash
curl http://192.168.31.139:9000/status
curl http://192.168.31.139:9000/navigation_route/status
```

第二个命令在未执行任务时应显示 `"state": "idle"`、`"active": false`。

6. 确认 AMCL 已经在 `first_floor` 地图中正确定位。若初始位置不准确，应先在 RViz 中使用 “2D Pose Estimate” 设置小车实际位置，并观察激光扫描与地图墙体基本重合。定位未收敛时不要开始路线。

## 5. 创建有序巡检路线

1. 进入“巡检任务管理”。
2. 点击创建巡检计划。
3. 在“巡检范围”选择“实验楼一”，确认预览图为实验楼一 `first_floor` 地图。
4. 进入“点位与路线”。
5. 在固定点位列表或地图上依次点击需要的巡检点。
6. 在“路线顺序”中检查最终顺序；可使用上移、下移、删除或“反向执行”调整。
7. 确认点位数量和顺序无误后点击“创建任务”。

点选顺序只是初始顺序，最终以下发前“路线顺序”列表从上到下的顺序为准。

### 5.1 固定点位模式

选择“固定点位”后，可从右侧固定点库或地图上的固定点标记选择 `LAB-P02` 至 `LAB-P06`。再次点击已选点会将其从路线移除。

### 5.2 自定义点位模式

1. 在“点位与路线”顶部选择“自定义点位”。
2. 页面会自动打开 `first_floor` SLAM 栅格图。
3. 在 SLAM 图白色自由空间中依次点击需要到达的位置。
4. 每次有效点击都会生成“自定义点1、2、3……”并按点击顺序加入路线。
5. 点击绿色覆盖区外、黑色墙体、灰色未知区或离障碍物过近的位置时，页面会拒绝添加并显示原因。
6. 在“路线顺序”中可上移、下移、删除或反向执行。
7. 每个自定义点可设置到点朝向：向东、向南、向西或向北。
8. 页面显示的 `map (x, y)` 是最终下发给 ROS `move_base` 的地图坐标。

单个任务应明确选择“固定点位”或“自定义点位”模式。切换模式不会删除另一模式中已经编辑的点，但创建任务时只保存当前模式的路线。

## 6. 下发和确认路线

1. 确认小车周围无人、无临时障碍，并安排人员随车观察。
2. 在新建任务所在行点击“开始”。
3. 前端将完整路线一次性发送给后端，后端再转发给 `192.168.31.139:9000/navigation_route`。
4. 车端接收成功后返回 `execution_id`；前端随后持续查询该执行编号。
5. 页面会显示“已到达 N / 总点数”。这表示车端已经确认前 N 个点的 `move_base` 结果为成功，并非前端按时间估算。
6. 当状态变为“已完成”时，表示车端已按顺序确认全部固定点或自定义点到达成功。

需要从小车终端独立核对时，可执行：

```bash
curl http://192.168.31.139:9000/navigation_route/status
```

重点字段：

- `execution_id`：本次整条路线的唯一编号。
- `state`：`queued`、`moving`、`arrived`、`completed`、`failed` 或 `cancelled`。
- `route_index`：当前执行到的路线位置。
- `reached_count`：车端已确认成功到达的点数。
- `point_id` / `point_name`：当前点位。
- `results`：已执行点位的逐点结果。
- `last_error`：失败原因。

## 7. 暂停与异常处理

- 点击任务“暂停”会向车端发送停止命令，取消当前 `move_base` 目标并停止该路线继续下发后续点。
- 任务显示 `failed` 时，先查看 `last_error`，排除定位丢失、规划失败、障碍物、底盘或传感器问题，再重新创建或重新开始任务。
- 若网络中断，前端会显示路线状态连接中断；不要直接认为任务完成，应先在小车终端查询 `/navigation_route/status`。
- 紧急情况优先使用车辆实体急停，不能只依赖网页按钮。

## 8. 停止车端服务

确认没有活动路线并且小车已经停止后，可在小车终端执行：

```bash
source /opt/ros/melodic/setup.bash
export ROS_MASTER_URI=http://192.168.31.139:11311
rostopic pub -1 /cmd_vel geometry_msgs/Twist '{}'
pkill -TERM -f 'roslaunch indoor_patrol_bringup web_navigation_control.launch'
pkill -TERM -f 'camera_mjpeg_server.py'
```

## 9. 首次实车验收建议

正式整线运行前，建议先在有人监护和低速条件下只选择两个相邻点进行验收，检查：

1. 地图、激光和 AMCL 位姿是否一致。
2. 前端路线顺序是否与车端 `results` 顺序一致。
3. 第一个点成功后，车端是否才开始第二个点。
4. 暂停、急停和失败状态是否能阻止后续点继续执行。

当前实现和联调没有向小车下发任何有效巡检目标，也没有直接启动车辆完成巡检。
